## 3. 核心技术决策

### 3.1 Streamlit vs React+FastAPI

| 维度 | Streamlit | React+FastAPI |
|------|----------|---------------|
| 开发速度 | 极高，一个 Python 文件即页面 | 慢，需要前后端分离 |
| UI 灵活性 | 中等，受限于组件库 | 高，完全自定义 |
| 面试 Demo | 一键启动，零配置 | 需要前后端分别启动 |
| 扩展性 | 有限，复杂交互需 session_state | 强，适合生产级产品 |

**选择**: Streamlit。理由：Lulu 非专业前端，优先保证 v1 快速落地和面试演示的流畅性。v2 如需要可迁移到 Next.js。

### 3.2 SQLite vs PostgreSQL

| 维度 | SQLite | PostgreSQL |
|------|--------|-----------|
| 安装配置 | 零配置，Python 标准库 | 需安装服务、配置连接 |
| 并发支持 | 单写多读 WAL 模式 | 高并发 |
| 面试 Demo | 拷贝即运行 | 需要数据库环境 |

**选择**: SQLite。理由：本地 Demo 场景不需要高并发，开箱即用是核心诉求。

### 3.3 计价单位模型设计

**核心决策**: 将"计价单位"作为商品的一等字段，而非隐含在业务逻辑中。

| 方案 | 描述 | 评价 |
|------|------|------|
| A: 隐式规则 | 硬编码某些商品类型锁定数量 | 不灵活，新增商品需改代码 |
| B: Unit 字段 | 每个商品绑定 unit 字段 | **选定方案** — 数据驱动，灵活可扩展 |

## 4. 算法与规则说明

### 4.1 商品编号生成算法

```
输入: 当前日期
步骤:
  1. 格式化日期: YYYYMMDD
  2. 查询当天已有商品数: COUNT(product_code LIKE 'P{date}-%')
  3. 序号 = 已有数 + 1
  4. 编号 = f"P{date}-{序号:03d}"
输出: 商品编号 (如 P20260609-001)
```

### 4.2 报价单编号生成算法

```
输入: 当前日期
步骤:
  1. 格式化日期: YYYYMMDD
  2. 查询当天已有报价单数: COUNT(quote_no LIKE 'Q{date}-%')
  3. 序号 = 已有数 + 1
  4. 编号 = f"Q{date}-{序号:03d}"
输出: 报价单编号 (如 Q20260609-002)
```

### 4.3 计价单位规则表

| 计价单位 (unit) | 数量行为 | 数量默认值 | 示例 |
|----------------|---------|-----------|------|
| project | 锁定不可编辑 | 1 | API Process Development |
| batch | 可编辑，整数 ≥ 1 | 1 | API GMP Manufacturing |
| study | 可编辑，整数 ≥ 1 | 1 | Stability Study |

### 4.4 报价金额计算公式

```
行总价 (line_total) = quoted_price × quantity  (SQLite GENERATED ALWAYS AS STORED)
报价汇总 (total_quoted) = Σ(line_total) for all line items
```

**注意**: 报价汇总按报价单价汇总，不按销售指导价汇总。指导价仅供编制时参考。

## 6. 组件树与路由

### 6.1 页面路由

```
Home.py                          # 登录页
  ├── login_form (st.form)
  └── redirect → pages/1_Product_Management.py

pages/1_Product_Management.py    # 商品管理
  ├── Tab: Product List          # st.dataframe / HTML table
  └── Tab: New Product           # st.form

pages/2_Quotation_Management.py  # 报价管理
  ├── View: list (default)       # HTML table + View buttons
  ├── View: create               # Basic info form + Line items table
  └── View: detail               # Basic info card + Line items table
```

### 6.2 Session State 管理

| Key | Type | 用途 |
|-----|------|------|
| `user` | dict | 当前登录用户信息 |
| `view` | str | 报价管理页当前视图 (list/create/detail) |
| `detail_quote_id` | int | 详情视图的报价单 ID |
| `line_items` | list[dict] | 创建报价单时的临时明细行 |

## 7. 数据库初始化流程

```
init_db() 调用时机: Home.py 启动、每个 pages/ 页面启动

流程:
  1. 创建 4 张表 (IF NOT EXISTS)
  2. 检查 users 表是否为空
  3. 如果为空 → 插入 2 个 demo 用户
  4. 检查 products 表是否为空
  5. 如果为空 → 插入 10 个 CDMO 商品
  6. 检查 quotations 表是否为空
  7. 如果为空 → 插入 3 个示例报价单 + 明细行
```

## 8. 边界与异常处理

### 8.1 输入校验

| 字段 | 校验规则 | 错误提示 |
|------|---------|---------|
| username | 非空 | "Please enter both username and password." |
| password | 非空 | 同上 |
| product_type | 非空字符串 | "Product Type is required." |
| guide_price | 数值 > 0 | "Guide Price must be greater than 0." |
| customer | 非空 | "Please fill in all Basic Information fields." |
| budget | 数值 > 0 | 同上 |
| requirement | 非空 | 同上 |
| line_items | 至少 1 行 | "Please add at least one line item." |
| quoted_price | 数值 > 0 | DB CHECK 约束 |
| quantity | 整数 ≥ 1 | DB CHECK 约束 |

### 8.2 降级策略

| 异常 | 策略 |
|------|------|
| SQLite 连接失败 | Python 异常冒泡，Streamlit 显示错误页面 |
| 报价单不存在 | 返回列表页，显示 error 提示 |
| 重复添加商品到报价单 | 前端拦截，warning 提示 |
